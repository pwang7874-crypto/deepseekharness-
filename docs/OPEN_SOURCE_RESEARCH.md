# 开源桌宠调研与融合记录

本项目只复用经过重新设计的产品机制与通用架构，不携带下列项目的角色图片、动画、声音或受限制前端代码。用户上传的角色资产仍由用户自行确认使用权。

## 调研项目

### NekoAI（MIT）

- 来源：https://github.com/nucket/NekoAI
- 优点：经典 Neko 状态序列、靠近/离开鼠标后的自然过渡、尺寸分级、透明窗口、自动漫游、情绪引擎、长时间工作提醒。
- 本项目采用：安全的自主动作调度、鼠标视线跟随、滚轮缩放、动作结束后自动回到稳定状态。

### Pet Mochi（MIT）

- 来源：https://github.com/cskwork/pet-mochi
- 优点：宠物不依赖 LLM 也能保持“活着感”；纯函数状态机；动作闭集；低打扰冷却；大量前后端行为测试；权限边界明确。
- 本项目采用：本地确定性动作选择、动作有限时长、夜间睡眠/哈欠、空闲微动作、独立测试以及显式开关。

### Oneko Swift（MIT）

- 来源：https://github.com/oneko-swift/oneko-swift
- 优点：极轻量、动作目的单一且反馈直接、鼠标驱动行为、原生桌面体验。
- 本项目采用：视线跟随、短动作反馈、交互后立即回归，不引入其角色素材。

### VPet（Apache-2.0；默认动画素材另有授权条件）

- 来源：https://github.com/LorisYounger/VPet
- 优点：头部抚摸、身体互动、举起/拖动、动作词典、角色和主题模组化。
- 本项目采用：头部与身体分区触摸、摸摸/玩耍/伸懒腰/睡觉互动菜单、用户角色资产与行为引擎分离。
- 未采用：VPet 自带动画和图片；这些素材具有独立版权与商业使用条件。

### Open-LLM-VTuber（当前前端为项目自定义许可）

- 来源：https://github.com/Open-LLM-VTuber/Open-LLM-VTuber
- 优点：自然语音打断、语音活动检测、情绪映射 Live2D 动作、宠物模式、触摸反馈。
- 本项目采用：自行实现的本地音量活动检测、停顿自动结束录音、开始录音时停止桌宠朗读，以及 DSH 情绪到有限动作词典的映射。
- 未复制其前端代码或角色素材。

## 已融合的体验原则

1. 桌宠在 DSH 没有输出时也会自主歪头、伸懒腰、摆动、打哈欠和睡觉。
2. 模型只输出情绪；本地动作引擎负责把情绪安全地映射成预定义动作，避免模型发明不存在的动画。
3. 用户可点击头部摸摸、点击身体挠痒、双击玩耍、右键打开互动菜单。
4. 图片动态角色、Live2D、VRM 与 GLB 共用一致的动作和视线语义。
5. 麦克风支持手动结束，也支持检测到讲话后的停顿自动结束；开始录音立即中断正在播放的 TTS，避免回声。
6. 自主动作、自动停录和触摸音效均可关闭。
7. 不在安装包中加入第三方角色资产，降低版权和供应链风险。
